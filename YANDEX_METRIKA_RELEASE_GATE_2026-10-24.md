## Непройденные ворота

1. **Recovery set и restore drill.** `/var/backups/ianep` имеет права `0700`, каталог приложения закрыт для `ianep-admin`. Разрешённая без пароля команда — только `/usr/local/sbin/ianep-deploy` без аргументов. Ни содержимое, ни контрольные суммы production backup set не получены; изолированное восстановление production БД и storage не выполнено. Текущие автоматические копии не дают доказанной согласованности БД и storage при продолжающихся записях. Требуется штатное согласованное окно без записей или подтверждённая snapshot-процедура, затем единый recovery set, проверка SHA-256, восстановление в отдельные БД и storage и проверка без вывода персональных данных. Секреты остаются на VPS.
2. **Миграция.** Wrapper допускает только закреплённую RBAC миграцию при точном старом SHA и отклоняет новую Prisma миграцию. Новая таблица `analytics_consent_events` нужна серверному журналу. Прямой `prisma migrate deploy` на VPS обходит защиту и не выполнялся. Требуется отдельная ревизия wrapper и runbook с проверкой exact target SHA, checksum SQL, подтверждённого recovery set и запуска миграции. SQL создаёт новую таблицу и два индекса, не меняя старых таблиц: старый код совместим с новой схемой, а кодовый откат после успешной миграции может оставить таблицу. Сценарии отказа сборки, DDL, restart и health требуют стендовой репетиции. Удаление таблицы как автоматический rollback недопустимо.
3. **Production SHA.** Чтение `/opt/ianep/app` для `ianep-admin` запрещено, поэтому точный production SHA не подтверждён; deploy-wrapper печатает его только после запуска, который меняет production и сейчас недопустим.
4. **Сниппет Яндекса.** Полный код действующего счётчика из авторизованного кабинета не получен. Нынешняя сессия браузера не показывает авторизованную вкладку Метрики. Побуквенная и семантическая сверка остаётся открытой. Не нужны логин, пароль или иной секрет в чате: достаточно открыть в доступном браузере страницу кода счётчика 113770883 либо передать её текст без учётных данных.
5. **Правовая оценка.** Псевдонимный UUID и время подтверждают действие конкретного браузера, но сами по себе не устанавливают личность субъекта. Пункт 3 статьи 9 закона № 152-ФЗ возлагает на оператора обязанность доказать получение согласия. До оценки применимости выбранной формы доказательства и опубликованных Privacy/Cookies юристом соответствие не подтверждено. [Текст статьи 9](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/).

## Следующее разрешённое действие

Оператор с доступом через штатную Beget/VPS консоль должен обеспечить согласованное окно, recovery set и изолированный restore drill по `docs/PRODUCTION_BACKUP_RESTORE.md`, затем проверить точный production SHA и согласовать изменение deploy-wrapper с миграционным планом. После этого повторить интеграционные и релизные проверки, сверить официальный сниппет и получить правовую оценку. Только при прохождении всех ворот выполнять push/deploy и production smoke без тестовых заявок.
