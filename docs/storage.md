# Закрытое хранилище IANep

## Использование

В материалах проекта и в публикации результата этапа выберите «Загрузить файл». После загрузки сохраните материал либо опубликуйте результат. До публикации файл администратора недоступен клиенту. Внешние ссылки по-прежнему доступны как альтернативный источник.

Файл: до 20 МиБ. Проект: до 1 ГиБ, включая незавершённые загрузки. Форматы: PNG, JPEG, WebP, PDF, ZIP, DOCX, XLSX, PPTX, TXT и CSV (UTF-8). Изображения можно просматривать в кабинете. Документы и архивы выдаются как скачивание. SVG, HTML, исполняемые файлы и неизвестные расширения не принимаются. Проверка сигнатуры — не антивирус и не полная проверка структуры Office/архива; антивирусное сканирование не подключено.

## Размещение

По умолчанию файлы находятся в `.ianep-storage` в корне проекта, вне `public` и Git. Для постоянного тома задайте `IANEP_STORAGE_DIR` — абсолютный путь, доступный процессу приложения. Один и тот же каталог должен использоваться приложением и командой очистки. Каталог не должен публиковаться веб-сервером или размещаться в `public`. Не используйте символические ссылки на публичные каталоги.

Создаваемые каталоги имеют права 0700, файлы — 0600. Приложение создаёт файлы через эксклюзивное создание, без перезаписи. Имена на диске — UUID, исходные имена хранятся в БД. Метаданные StoredFile содержат проект, автора, сторону, дату, размер, проверенный тип и SHA-256. При выдаче проверяется контрольная сумма. Замена работы создаёт новый файл; ранее опубликованные версии продолжают ссылаться на старые байты.

Миграция: `20260907180000_private_storage`. Добавлена таблица `stored_files` и необязательные внешние ключи `fileId` у VersionMaterial и ProjectMaterial. Старые ссылки сохранены. Материалы файла используют защищённый адрес `/api/files/[id]`.

## API

- `POST /api/projects/[id]/files?side=ADMIN|CLIENT&name=имя` — тело содержит байты файла, автор берётся из соответствующей сессии. Проверяются Origin, доступ к проекту, потоковый лимит размера, сигнатура и квота. Возвращается идентификатор файла для последующего прикрепления через существующие Server Actions.
- `GET /api/files/[id]` — Admin либо клиент этого проекта. Клиент видит свои загрузки и прикреплённые материалы/результаты. Неопубликованный файл Admin ему недоступен. Ответ без публичного кеширования, с nosniff, sandbox, same-origin. Изображения выдаются inline; `?download=1` принудительно скачивает. Остальные форматы выдаются attachment.
- Прикрепление через Server Actions повторно проверяет проект файла. Клиент может прикрепить только собственную загрузку. Тип и адрес берутся из БД, не из присланных полей.

Лимит одновременных загрузок: 4 на процесс, 2 на аккаунт; чтение тела — до 60 секунд. Файлы ограниченного размера буферизуются в памяти для проверки. Для нескольких серверов нужны общий том либо объектное хранилище и общий лимитер. Behind reverse proxy должен сохраняться корректный адрес запроса для проверки Origin; лимит тела на прокси должен позволять 20 МиБ. Serverless с непостоянным локальным диском не подходит для этого адаптера.

## Очистка

`npm run storage:cleanup` удаляет незакреплённые загрузки старше 24 часов и оставшиеся после сбоя файлы без записи БД того же возраста. Прикреплённые материалы и файлы версий не удаляются. Проверка выполняется под той же блокировкой проекта, что публикация, чтобы избежать гонки. Команда запускается вручную; расписание не создавалось.

Если загрузка завершилась, но форму не сохранили в течение суток, после очистки файл потребуется загрузить заново. При отказе записи БД приложение пытается удалить созданный файл; уборка подбирает остатки после аварийного завершения процесса.

## Резервное копирование и перенос

Храните резервные копии БД PostgreSQL и каталога файлов как единый комплект. Для простого согласованного снимка остановите запись в приложение и команду очистки, сохраните БД и каталог, затем возобновите работу. При восстановлении сначала восстановите оба компонента в закрытом окружении, задайте тот же каталог через IANEP_STORAGE_DIR и проверьте скачивание файла с авторизацией. Резервное копирование не подключено автоматически.

S3/MinIO, антивирус, шифрование на уровне тома, автоматические резервные копии, интерфейс удаления прикреплённых файлов и архивирование содержимого внешних URL в этот этап не входят. Документы платежей пока остаются внешними ссылками; файл можно добавить в общие материалы проекта.

## Проверки

Lint, TypeScript, integration tests и production build. Интеграционные сценарии: доступ владельца/постороннего, приватность черновика Admin, публикация файла, запрет использования файла другого проекта, новые байты без изменения предыдущей версии, определение повреждения по SHA-256, лимит 20 МиБ, запрет поддельного формата и обхода пути.

В браузере: вход клиента, загрузка TXT, автоматическое название, ожидание загрузки, сохранение материала и появление в журнале. HTTP: исходное содержимое с авторизацией, attachment/no-store; без сессии 401; чужой Origin 403.
